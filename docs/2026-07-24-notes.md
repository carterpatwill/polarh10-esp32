## 1. Activity model retrain

### The pipeline (reminder)
Data is recorded on the Pi, pulled to the Mac, filed into the **library**, then the
model trains on the library. `activity.py` is the current trainer (`har.py` is
superseded).

- **Dump** — `data/hr_data.db` — latest pull from the Pi. Temporary.
- **Library** — `data/labeled_data/labeled_walks.db` — permanent training data.
- **Model** — `data/labeled_data/activity_model.joblib`.

Loop:
```bash
./dump-pi.sh                 # pull from Pi (see note below about NOT wiping)
cd data
python3 activity.py add      # file new labeled dump sessions into the library
python3 activity.py buckets  # sanity-check counts per bucket
python3 activity.py train    # retrain -> activity_model.joblib
python3 activity.py guess N  # classify a session
```
Note: the project `.venv` is currently moved to `.venv/_venv_backup_esp32polar/`,
so I ran everything with system `python3` (pyenv), which has numpy/sklearn/joblib.
The README's `source ../.venv/bin/activate` line won't work as written until the
venv is restored.

### New tool: `data/trim.py`
Long sprint/run recordings bled into walking once you slowed down — a 130s "Sprint"
that was ~16s sprint + ~113s walking. That poisons the bucket and made the model
swap walk<->sprint. `trim.py` cuts a session down to just the vigorous window.

```bash
python3 trim.py 29                 # VIEW: per-second intensity bar, find where sprint ends
python3 trim.py 29 --keep 1 17     # CUT: keep seconds 1-17, delete the rest (backs up DB first)
python3 trim.py 29 --keep 1 17 -y  # skip the confirm prompt
```
- Edits the **library** by default. Backs the whole DB up to `data/dumps/` before
  any delete (files named `labeled_walks_pretrimNN_<timestamp>.db`), so trims are
  reversible.
- After trimming, retrain: `python3 activity.py train`.

### Results
- Before trim (with the bad tails): **34%** honest accuracy, walk<->sprint swapped.
- After trim: **64%**, and the walk/sprint swap is gone (walk 95%, sprint 57%, run 59%, jog 78%).
- `other` (Sitting) still scores **0%** — but that's mostly a **measurement artifact**:
  there's only ONE `other` session, and the honest score holds each session out, so
  when the single `other` session is held out the model has never seen `other`.
  Excluding `other`, the gait classes are ~79%.

## 2. ESP32 "offline but light solid on" fix

### The bug
Symptom: status light **solid on**, but the control page shows **"ESP not found."**

- The status LED only tracked the **BLE strap** link. Solid = strap connected.
- It did **not** track the network. So if WiFi/MQTT dropped while the strap stayed
  connected, the light stayed solid while the ESP was actually offline.
- The `loop()` had **no WiFi-reconnect logic** — `WiFi.begin()` only ran in `setup()`.
  Once the uplink dropped, it stayed dead until a power-cycle.
- Likely trigger: the **iPhone hotspot** (tried first) sleeps/drops idle clients,
  made worse because modem sleep wasn't disabled.

### The fix (in `esp32/src/main.cpp`)
1. **Auto-reconnect WiFi** — extracted boot join into `connectWiFi()`; added
   `ensureWiFi()` called every loop. On a drop it lets the SDK auto-reconnect for
   `WIFI_RECONNECT_MS` (10s), then re-walks the full network list and brings MQTT
   back. No more "dead until reboot."
2. **Anti-drop settings** in `connectWiFi()`: `WiFi.setSleep(false)` and
   `WiFi.setAutoReconnect(true)` (+ `WiFi.persistent(false)`).
3. **Honest LED** — new `updateStatusLed()`:
   - fast blink → WiFi down
   - slow blink → WiFi up but strap or MQTT broker missing
   - **solid on → fully online (WiFi + broker + strap)**
   So "solid but not found" can no longer happen — if the page can't see it, it blinks.

Build verified: `pio run -e xiao-esp32s3-polar` → SUCCESS.
